# 过程沟通

沟通完成不等于消息已发送。至少应形成共识、理解校验、行动承诺、偏差暴露和可追踪结果。

## 开工约定

非简单任务先约定：

- 交付物和阶段出口；
- 哪些事项自动同步，哪些必须立即同步；
- 业务、安全和权限硬门禁；
- 进度与证据放在哪里；
- 暂停后如何恢复。

## 默认同步节点

1. 初步调查后：目标、范围基线、未知项和验收是否成立。
2. 复杂方案形成后：只请用户确认真正影响契约或范围的取舍。
3. 关键里程碑：已完成证据、覆盖率、下一步和风险。
4. 最终交付：范围差集、技术验证、独立复审、业务验收和遗留项。

目标或范围变化、重大风险、额外权限、真实阻塞、无法完整交付时立即沟通。计划内普通实现细节不额外打扰。

## 理解校验

发送信息后追问对方怎么做，比问“明白了吗”有效。Agent 对重要歧义使用：

```text
我理解的是 X；如果实际是 Y，交付物会变为 Z。按哪个目标推进？
```

对方已明确回答过的问题不重复问。

## 风险格式

```text
事实：已经观察到什么，证据在哪里。
影响：影响哪个目标、范围或时间。
未知：还需要验证什么。
建议：推荐动作；若需授权，指出具体权限。
```

不隐瞒坏消息，也不把所有内部返工细节倾倒给用户。

## 进度格式

开头一句话回答“整体到什么程度、卡不卡、要不要人管”，然后：

```text
总目标：[当前阶段] → [后续阶段]
本轮：[已实现未验收] → [正在验证] → [未开始]

✅ 已完成：带覆盖率和证据。
🔜 接下来：下一动作和进入条件。
🙋 需要你：推荐方案；没有则写“暂无，你无需操作”。
```

状态符号统一为：

- `✅` 已独立验收通过；
- `◐` 已实现但未独立验收；
- `▶` 正在进行；
- `○` 未开始；
- `⛔` 阻塞，必须紧跟原因。

`✅` 只用于已独立验收；agent 自称完成但未核验只能是 `◐` 或 `▶`。总目标行按任务卡/PRD 的阶段骨架展示，不因当前这一轮的小任务改写阶段顺序；并行任务用分支表示。内部 task、attempt、ledger 编号放到证据行。

## 行动闭环

关键讨论形成可追踪条目：

```text
结论 | 执行者 | 下一同步节点 | 验证或业务动作
```

Slack、Issue、ledger 等工具用于留痕和提醒，不替代关键对话。远程异步沟通对重要决策仍要做复述确认。
