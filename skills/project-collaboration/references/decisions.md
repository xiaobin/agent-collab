# 决策边界与记录

## 判断口径

同时满足以下条件，agent 可在目标内自主决定：

1. 可逆；
2. 不超出已确认范围；
3. 不改变对外契约或验收标准；
4. 不产生未授权的外部影响。

任一条件不满足，暂停相关步骤并交回用户。其他不依赖该决策的工作可以继续，不必让整个任务停摆。

## 必须交回用户

- API、数据模型、消息主题与 payload、登录或令牌语义、租户模型、前端兼容承诺等契约变化。
- 扩大或缩减范围，修改验收口径，把未通过项解释为通过。
- 跳过、降级或删除目标范围内的功能。
- 放开白名单、关闭沙箱、跳过鉴权、降低安全或隐私边界。
- 发布、部署、生产配置、共享数据库 migration、第三方平台变更。
- 未明确授权的提交、推送、删库、删表、删分支或关闭非本次创建的资源。
- 未知审批弹窗、额外授权请求，以及无法按原验收完整交付。

## 不应反复询问

实现方案、文件落位、任务拆分、并行度、agent 选型、普通修复、补充测试、复现取证，以及已冻结规范内的可逆技术选择，由协调者负责。

## 请求决策的格式

```text
需要你决定：<一个具体问题>
推荐：<一个方案>
理由：<为什么>
影响：<范围、契约、安全、时间或可逆性>
授权后动作：<接下来具体做什么>
```

有 AskUserQuestion 等结构化工具时，用它承载真正的用户选择；不要把可自主的技术细节伪装成用户决策。

## 自主决策记录

重要或影响后续工作的自主决策，在项目 ledger 或任务记录中追加：

```json
{
  "event": "decision",
  "goal_ref": "目标来源",
  "question": "需要选择什么",
  "options": ["候选方案"],
  "chosen": "实际选择",
  "rationale": "与目标和约束的关系",
  "reversible": true
}
```

记录用于事后追溯和推翻，不是为了把责任转嫁给用户。新证据推翻旧决策时，追加更正或新决策，不改写历史。
